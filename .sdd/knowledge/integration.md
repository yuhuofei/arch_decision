## 1. 触发条件

```
IF 需要与外部系统交互（第三方 API / SaaS / 合作方系统 / 遗留系统）THEN 读取本文件
```

## 2. 接入方式选择（`Matrix §15`、`Matrix §16`）

| 方式 | 适用 | 代价 |
| --- | --- | --- |
| 同步 REST | 需要即时结果、用户等待 | 对方不可用会拖慢本服务 |
| gRPC | 内部服务间、强类型、高性能 | 生态与调试成本 |
| Webhook（入向） | 对方主动通知事件 | 需验签 + 幂等 + 重放防护 |
| Polling | 对方无 webhook | 延迟与配额消耗 |
| 消息队列 | 异步、削峰、解耦 | **+1~+2 复杂度**（`decision-protocol.md` §5.1） |
| SFTP / 批量文件 | 遗留系统、对账 | 无实时性、需完整性与重跑设计 |
| CDC | 复用对方数据库变更 | 强耦合，通常只在同组织内 |

```
默认优先同步 REST（最小复杂度）。
IF 对方不可靠 OR 调用耗时超过用户可等待时间 OR 需要削峰
THEN 改为异步（队列 / 后台任务），并接受其复杂度预算。
```

## 3. 每次接入必须写清的契约（本仓补充）

**外部系统是本仓最大的不确定性来源**。接入前必须逐项落定，缺项即 `BLOCKED`（`decision-protocol.md` §6.2）：

```
认证方式       API Key / OAuth / mTLS / 签名（知识库 §35）
超时           连接超时与读超时分开；必须显式设置，禁止依赖默认
重试           可重试错误（5xx / 429 / 网络）与不可重试（4xx 参数错）必须区分
幂等           写操作必须带幂等键，否则重试 = 重复副作用（知识库 §8）
限流           对方的配额与本方的节流；本仓对外同样需要（res.md §72）
错误语义       对方错误的映射：哪些可降级、哪些必须冒泡给用户
对账 / 补偿    异步链路最终一致性靠什么收敛
配额与成本     按调用量计费的必须做 Cost 复核（decision-protocol.md §4.2）
```

## 4. 出站调用的防线（`res.md §72` + 本仓补充）

```
超时  → 必须显式；无超时 = 线程池最终被拖死
重试  → 指数退避 + jitter + 上限；仅对幂等操作或带幂等键的操作重试
熔断  → 下游故障会拖垮本服务时引入（见 knowledge/reliability.md）
隔离  → 关键下游与非关键下游使用独立连接池/线程池，避免互相阻塞
降级  → 设计好"对方不可用时返回什么"，不要只抛 500
```

## 5. 入站回调的防线（本仓补充）

```
1. 验签 —— 必须校验来源签名/密钥，不能只靠"URL 是私密的"
2. 幂等 —— 回调会重放，必须用事件 id 去重
3. 限流 —— 回调端点同样要限流，否则会被刷
4. 快速确认 + 异步处理 —— 避免对方超时重发造成放大
5. 时间戳窗口 —— 拒绝过期回调，防重放攻击
```

## 6. 复杂度与成本口径

- 引入 MQ 承载集成：按 `Matrix §16` 选型，复杂度计 `+1`（RabbitMQ/Redis Queue 独立实例）或 `+2`（Kafka）。
- SDK / HTTP 客户端库**不计分**。
- 外部 API 按调用计费时必须量化到月，写入 `decision.json` 的 `cost`。

## 7. 与验证的衔接

`verification.md` 必须覆盖：**对方超时**、**对方返回 5xx**、**重复回调**三种失败路径。
只测"正常返回"不构成集成验证。
