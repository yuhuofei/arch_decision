# Knowledge: Data Lifecycle（数据生命周期 / 合规）

> 来源：`res.md §2.4`（Data，含 retention）、`res.md §45`（SECURITY，含 audit）、
> `res.md §48`（LOGGING，含 PII）、`res.md §65`（BACKUP）、`res.md §41`（AUTHENTICATION，含加密）；
> `知识库 §35`（API Security，含 audit）。`modv2.md §19` 列为缺失决策维度。
> **为什么要单独一条决策线**：`Compliance` 与 `Data residency` 已被列为默认 `REQUIRE_CONFIRMATION`
> （`decision-protocol.md` §6.4），但若没有对应知识，Agent 只会"知道要问"，**不知道该问什么**。
> **重要说明**：源文档只有零散的加密/审计/日志条目，本文件多数条目标注「本仓补充」。
> 治理：`.sdd/decision-trees/decision-protocol.md`　相邻：`knowledge/database.md`、`knowledge/security.md`

---

## 1. 触发条件

```
IF 任一成立 THEN 读取本文件：
  - 处理个人数据（PII）/ 支付 / 健康 / 未成年人数据
  - 有留存期、删除权、导出要求
  - 有审计或追溯要求
  - 跨法域存储或传输
```

## 2. 数据分级（本仓补充）——先分级，再决定一切

| 级别 | 例子 | 最低要求 |
| --- | --- | --- |
| L1 公开 | 商品目录、文档 | 完整性保护 |
| L2 内部 | 运营指标、内部配置 | 访问控制 + 传输加密 |
| L3 个人数据（PII） | 手机号、地址、身份证 | 加密（静置 + 传输）+ 最小化收集 + 留存期 |
| L4 敏感 / 受监管 | 支付凭证、密码、健康、生物特征 | 专用存储 + 审计 + 严格留存 + 合规审查 |

> **禁止**把 L3/L4 数据写进日志或错误堆栈（`res.md §48`）。日志脱敏在写入前完成，不是查询时过滤。
> L4 一出现，`Compliance` / `Data residency` 即进入 `REQUIRE_CONFIRMATION`，**不得静默决定**。

## 3. 留存与删除（`res.md §2.4` + 本仓补充）

```
对每一类 L3/L4 数据必须写明三件事：
  retention   = 存多久（到期自动清理，而不是"一直存着"）
  deletion    = 用户/客户要求删除时，多久内真删（含备份与副本）
  legal hold  = 哪些情况不得删（争议、审计期）

禁止：retention = "永久" 而不写明理由
```

**删除必须覆盖副本**：备份、只读副本、搜索索引、缓存、分析仓库。
只删主库 = 未完成删除。删除机制属 `REQUIRE_CONFIRMATION`（不可逆）。

## 4. 加密与审计（`res.md §41`、`res.md §45`）

```
传输      TLS 全链路（含服务间），默认必做，不是可选
静置      L4 必须；L3 在托管数据库的默认加密之外，敏感字段（如身份证）另做字段级加密
密钥      存密钥管理服务，禁止进仓库 / 镜像 / 环境变量明文（见 knowledge/configuration.md）
审计      L4 的读写与权限变更必须留审计日志（res.md §45）
```

**审计日志与业务日志分离**：审计日志需要防篡改与更长留存，不能和普通日志同库同策略。

## 5. 导出 / 导入与可携带性（本仓补充）

```
IF 有合规要求或企业客户 THEN 需要导出（数据可携带）与导入（迁移）能力
约束：导出必须走授权 + 审计 + 限流；大导出走异步任务而非同步请求
```

## 6. 数据驻留（Data Residency）（本仓补充）

```
IF 数据不得离开某法域 THEN 存储、备份、日志、分析仓库、第三方 SaaS 都要在该区域内
```

**易漏点**：日志收集器、错误上报、APM、CDN、对象存储的生命周期规则都可能把数据带出国境。
核对时按"数据流向清单"逐个组件过，而不是只看主数据库。

## 7. 复杂度与成本口径

- 加密 / 脱敏 / 审计表**不新增独立组件，计 0 分**。
- 专用合规存储、独立审计库、跨区域副本按 `decision-protocol.md` §5.1 口径计。
- 留存与审计会持续增加**存储成本** → 按 `decision-protocol.md` §4.2 做 Cost 复核。

## 8. 与验证的衔接

`verification.md` 的 Security 节必须能回答：L3/L4 字段清单、脱敏是否生效、
删除是否覆盖副本、审计日志是否可查。**未做删除验证的不得判 PASS。**
